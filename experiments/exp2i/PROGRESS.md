**Two loader paths + a twin**, generalized from `battery_2h`'s
single-size shape to take `repo` explicitly: `load_checkpoint` (clean-
dir path; the config is fetched fresh per entry from the ENTRY'S OWN
commit rather than one size-wide pin — 2h had a single commit for the
whole size, 2i has 22 distinct 7B revisions plus the 1B endpoint and
has no commit that covers them all, so `clean_dir` only hardlinks
candidate files and `load_checkpoint` fetches+passes the `AutoConfig`
object directly rather than writing a `config.json` into the clean
dir, which `from_pretrained(..., config=config)` does not require),
`load_thin` (plain `from_pretrained(repo, revision=commit)` through
the ordinary HF cache — `main`'s descriptive reading and the
preflight), `load_twin_7b` (seeded `from_config`,
`torch.manual_seed(seed)` immediately before construction, config
pinned at `REV_7B_ENDPOINT`'s commit). `clean_dir`/`free_checkpoint`
take an explicit `rev_key` decoupled from `download_entry`'s own
Hub-derived cache path (keyed by `entry["revision"]`), so a sweep can
key its clean dirs by grid step while the raw HF cache is keyed by
branch name — a deliberate signature difference from 2h's single
`_rev_dir(size, step, cache_root)`, noted here as a design decision
rather than left implicit. All lazy-import
`torch`/`transformers`/`huggingface_hub` inside the function body;
none executed by any test (`test_loader_family_present_and_not_executed`
asserts existence/callability only, and that `ck.tensor_digest` is
reused, not redefined — `bi.ck is ck`).
